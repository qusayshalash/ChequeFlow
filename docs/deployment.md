# النشر على خادم حقيقي

هذا الدليل يشغّل النظام كاملًا — قاعدة البيانات، تخزين صور الشيكات، الـAPI، لوحة
الويب، وبوابة HTTPS — على **خادم واحد فيه Docker**، من أي مزوّد.

لم يُختر مزوّد بعينه عن قصد: الملفات تعمل على أي خادم Linux، والاختيار (التكلفة،
موقع البيانات، الدعم) قرار صاحب المنشأة. الشيء الوحيد المطلوب من المزوّد: خادم
بعنوان IP ثابت، ومنفذا 80 و443 مفتوحان.

كل ما في هذا الدليل يُشغَّل فعليًا في CI مع كل دفعة (وظيفة `production stack`):
بناء الصورتين، تشغيل المكدّس، إنشاء أول مالك، تسجيل الدخول عبر HTTPS، رفع صورة شيك
وفتحها عبر رابطها الموقَّع.

## ما تحتاجه

|              |                                                                                      |
| ------------ | ------------------------------------------------------------------------------------ |
| خادم         | Linux، ‏2 غيغابايت ذاكرة على الأقل، Docker وDocker Compose                           |
| نطاقان       | واحد للنظام (`cheques.example.com`) وواحد لصور الشيكات (`files.cheques.example.com`) |
| DNS          | سجلّا `A` للنطاقين يشيران إلى عنوان الخادم — **قبل** أول تشغيل                       |
| قارئ الشيكات | اختياري: `OCR_PROVIDER=disabled` للإدخال اليدوي دون مفتاح، أو `claude` أو `google`   |

صور الشيكات على نطاق مستقل لسبب تقني: رابط الصورة الموقَّع يحمل اسم المضيف
ومساره بالضبط، وتقديم التخزين تحت مسار يعيد البوابة كتابته كان سيُبطل كل توقيع.

## 1) الإعدادات

```bash
git clone https://github.com/qusayshalash/ChequeFlow.git && cd ChequeFlow
cp infrastructure/.env.production.example infrastructure/.env.production
```

املأ `infrastructure/.env.production`. ولّد كل سرّ **على الخادم نفسه**:

```bash
openssl rand -hex 32      # كلمة مرور قاعدة البيانات، سرّا الجلسات، سرّ التخزين
openssl rand -base64 32   # FIELD_ENCRYPTION_KEY — بالضبط 32 بايت
```

هذا الملف يحمل كل أسرار النظام، و`.gitignore` يستبعده — لا تنسخه إلى أي مكان
مشترك.

> **متغيّرات الصدفة تتغلّب على هذا الملف.** `docker compose` يعطي أي متغيّر
> مُصدَّر في جلسة الطرفية أولوية على `--env-file`. إن كان `OCR_PROVIDER` أو أي
> اسم آخر من الملف مُصدَّرًا في صدفتك، فهو الذي يُستعمل — بصمت. شغّل الأوامر من
> جلسة نظيفة. اكتُشف هذا حين شغّل CI المكدّس أول مرة: متغيّر من إعدادات CI غلب
> الملف، فرفض الـAPI الإقلاع.

> **احتفظ بنسخة من `FIELD_ENCRYPTION_KEY` خارج هذا الخادم.** أرقام الحسابات
> مشفّرة به، في قاعدة البيانات وفي كل نسخة احتياطية. إن ضاع، لا يستطيع أحد قراءتها
> مجددًا. واستعادة نسخة احتياطية على خادم بمفتاح مختلف تُرفض — النظام يفحص ذلك
> قبل أن يكتب شيئًا.

## 2) التشغيل

```bash
docker compose --env-file infrastructure/.env.production \
  -f infrastructure/docker-compose.prod.yml up -d --build
```

ما يحدث بالترتيب: تقلع قاعدة البيانات والتخزين، يُنشأ مخزن الصور، تُطبَّق
هجرات قاعدة البيانات، ثم يقلع الـAPI — ولا يقلع قبل أن تكتمل الهجرات. وتحصل
البوابة على شهادتي HTTPS للنطاقين تلقائيًا وتجدّدهما بنفسها.

تحقّق:

```bash
curl https://cheques.example.com/api/v1/health
```

## 3) أول حساب

قاعدة البيانات فارغة، ولا أحد يستطيع الدخول بعد. أنشئ المنشأة ومالكها **مرة
واحدة**:

```bash
docker compose --env-file infrastructure/.env.production \
  -f infrastructure/docker-compose.prod.yml run --rm \
  -e ORG_NAME="اسم المنشأة" -e ORG_TIMEZONE=Asia/Hebron -e ORG_CURRENCY=ILS \
  -e OWNER_NAME="اسمك" -e OWNER_EMAIL=you@example.com -e OWNER_PASSWORD='…' \
  migrate /repo/node_modules/.bin/tsx /repo/packages/database/prisma/bootstrap.ts
```

- كلمة المرور تخضع لقاعدة النظام نفسها: 10 أحرف على الأقل، حرف كبير وصغير ورقم.
- المنطقة الزمنية تحدّد متى يبدأ «اليوم» في السجلات، ومتى تصل التذكيرات (8 صباحًا).
- يرفض العمل إن وُجدت أي منشأة — تشغيله مرتين بالخطأ لا يمسّ شيئًا.
- لا يُنشئ بيانات تجريبية: فقط المنشأة، فرعًا رئيسيًا، أماكن حفظ الشيكات، الأدوار، قائمة البنوك، والمالك.

ادخل إلى `https://cheques.example.com` بالحساب الجديد.

## 4) تطبيق الجوال

التطبيق المبني للمتجر يجب أن يعرف عنوان الخادم، ويُكتب **في إعداد البناء نفسه**،
لا في `apps/mobile/.env`: بناء EAS يجري في السحابة ويتجاهل ما يتجاهله git، و`.env`
منها — فالسطر لن يصل إلى البناء أبدًا. في `apps/mobile/eas.json`، داخل ملف البناء
الإنتاجي:

```json
"production": {
  "env": { "EXPO_PUBLIC_API_URL": "https://cheques.example.com/api/v1" }
}
```

(أو كمتغيّر بيئة في لوحة EAS للمشروع.) بدونه يبحث التطبيق عن الخادم على الشبكة
المحلية كما في التطوير، ولن يجده.

## 5) النسخ الاحتياطي

`scripts/server-backup.sh` ينسخ قاعدة البيانات وصور الشيكات إلى خارج الخادم، مشفّرة
**قبل** أن تغادره، فلا يقرؤها مزوّد التخزين. يحتفظ بـ7 نسخ يومية و4 أسبوعية و6 شهرية.
وظيفة `production stack` في CI تأخذ نسخة، تحذف كل البيانات، تستعيدها، ثم تفتح الشيك
وصورته.

**الإعداد مرة واحدة:**

1. أنشئ مخزنًا (bucket) ومفتاح وصول خاصًا به لدى مزوّد متوافق مع S3، مثل Cloudflare R2.
2. انسخ `infrastructure/.env.backup.example` إلى `infrastructure/.env.backup` واملأه.
   ولّد `RESTIC_PASSWORD` بالأمر `openssl rand -hex 32`.
3. جرّب: `bash scripts/server-backup.sh`
4. جدوِله يوميًا، الساعة 01:00 بتوقيت UTC:

```bash
echo '0 1 * * * root /root/ChequeFlow/scripts/server-backup.sh >> /var/log/chequeflow-backup.log 2>&1' > /etc/cron.d/chequeflow-backup
```

**احتفظ خارج الخادم، كلٌّ في مكان آمن، بما يلي:**

| ماذا                   | لماذا                                         |
| ---------------------- | --------------------------------------------- |
| `RESTIC_PASSWORD`      | من دونه لا تُفتح أي نسخة احتياطية             |
| `FIELD_ENCRYPTION_KEY` | من دونه لا تُقرأ أرقام الحسابات بعد الاستعادة |
| مفتاح الوصول للمخزن    | للوصول إلى النسخ من خادم جديد                 |

**الاستعادة، على هذا الخادم أو على خادم جديد:** ثبّت النظام، وضع في
`.env.production` قيمة `FIELD_ENCRYPTION_KEY` نفسها، وضع `.env.backup`، ثم:

```bash
bash scripts/server-restore.sh                  # يعرض النسخ المتاحة
bash scripts/server-restore.sh latest --confirm # يستبدل كل ما على الخادم
```

ونسخة النظام الاحتياطية من صفحة الإعدادات تبقى متاحة أيضًا، لكنها لا تحمل الصور.

## 6) التحديث

```bash
git pull
docker compose --env-file infrastructure/.env.production \
  -f infrastructure/docker-compose.prod.yml up -d --build
```

الهجرات الجديدة تُطبَّق تلقائيًا قبل أن يقلع الـAPI الجديد.

## ما ليس هنا بعد

- **البريد الإلكتروني**: لا يوجد مزوّد بريد، فلا «نسيت كلمة المرور». المدير
  يعيد تعيين كلمة أي مستخدم من صفحة المستخدمين.
- **المراقبة**: لا تنبيه إن توقف الخادم. فحص دوري لـ`/api/v1/health` من خدمة
  خارجية يكفي كبداية.
- **حجم الصورتين**: كل صورة تحمل اعتماديات البناء كاملة (قرابة غيغابايت). اختيار
  مقصود للمرحلة الأولى — الأبسط والأضمن — ويمكن تقليصه لاحقًا.
