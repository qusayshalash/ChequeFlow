## كيف تم التحقق

الجهاز بلا Docker، فأُعيد نفس أسلوب المرحلة الأولى:

- **PostgreSQL حقيقي** عبر PGlite على البروتوكول السلكي — طُبِّقت الترحيلة الثالثة،
  ونُفِّذ الـseed، ومرّت 45 اختبار تكامل (منها 18 جديدة تغطي نقاط هذه المرحلة، فتلتقطها
  CI ولا تعتمد على تشغيل يدوي).
- **خادم S3 مصغّر** لمسار رفع الصور.
- **الـAPI المبنية شُغِّلت فعليًا** وجرى استدعاء كل نقطة نهاية جديدة عبر HTTP:
  49 فحصًا، كلها ناجحة.

## أخطاء حقيقية كشفها التشغيل الحي

1. **عملة تختفي من اللوحة كليًا.** قائمة العملات كانت تُشتق من المجموعات نفسها،
   فعملة كل شيكاتها مسودة لم تكن تظهر بأي رقم. صار الاشتقاق من كل شيكات المنشأة.
2. **الشيك المحصَّل لا يظهر في أي مؤشر.** لم تكن هناك مجموعة تغطي `CLEARED` —
   وهذا هو سبب بلاغ «اللوحة أصفار والقائمة مليئة». أُضيفت `cleared` و`draft`
   و`returned`.
3. **`toChequeSummary` كان عرضة لخطأ صامت.** بعد إضافة معامل `today`، كان
   `rows.map(toChequeSummary)` سيمرّر فهرس المصفوفة كتاريخ. جُعل المعامل مطلوبًا
   من نوع `string` فصار الاستدعاء الخاطئ خطأ ترجمة لا خطأ وقت تشغيل.

## إصلاحات بعد مراجعة الكود

مراجعة لاحقة كشفت **ميزتين تدّعيان أنهما تعملان وهما لا تعملان** — وهو أسوأ من غيابهما، لأنه يمنح ثقة في غير محلها:

| الخلل                   | الحال قبل                                              | الحال بعد                                                       |
| ----------------------- | ------------------------------------------------------ | --------------------------------------------------------------- |
| المسودات دون اتصال      | تُحفظ ولا يرفعها شيء أبدًا — الشيك يضيع                | طابور حقيقي يُرفع تلقائيًا عند عودة الاتصال (ADR-031)           |
| قفل البصمة              | حالة في الذاكرة تُنسى عند إعادة التشغيل ولا تحرس شيئًا | يُحفَظ ويغلّف كل الشاشات ويُعاد عند العودة من الخلفية (ADR-032) |
| التصدير فوق 5000 صف     | يقتطع بصمت                                             | ترويسات + سطر تحذير داخل الملف (ADR-033)                        |
| كشف الحساب فوق 50 شيكًا | يقتطع بصمت                                             | يُعاد العدد الحقيقي وتقوله الواجهة (ADR-033)                    |
| تأجيل تنبيه مؤكَّد      | ينجح ثم يعيد 404                                       | يعيد 200 والصف المحدَّث (ADR-034)                               |

## غير مُنفَّذ عمدًا في هذه المرحلة

| البند                        | السبب                                                        |
| ---------------------------- | ------------------------------------------------------------ |
| استعادة نسخة احتياطية        | التصدير مُنفَّذ؛ الاستعادة تحتاج تصميم تعارضات لم يُطلب بعد  |
| تصدير PDF                    | CSV يغطي Excel وSheets؛ PDF يحتاج حزمة تخطيط عربي            |
| Push Notifications           | البنية جاهزة (حقل `channel`)، والتسليم يحتاج حساب FCM/APNs   |
| تعدد الشركات                 | المخطط يدعمه (`organization_id` في كل جدول)، ولا واجهة تبديل |
| تحديد عدة شيكات وإجراء جماعي | يحتاج تصميم تدقيق للإجراء الجماعي (من وافق على ماذا بالضبط)  |

## ما لا يزال غير قابل للتحقق على هذا الجهاز

- Docker Compose نفسه وMinIO الحقيقي (لا Docker).
- محاكي iOS (لا Xcode).
- نداءات Google Vision الحقيقية (لا مفاتيح — المزوّد يسقط إلى Mock بتحذير صريح).
